The simulated oracle and market are not production data. Do not use this runbook to infer authorization to deploy, fund or broadcast.

Budget Base registry/receiver creation and signal transactions, Lasna reactive creation/configuration/retry, destination callback charges, Unichain source vault and locked 0.001 test ETH, transaction L1 data and operator fees. ## Manifest and frontend fields

Record network and chain IDs, deployment block and transaction receipts, code hashes, mock asset/market/adapter/oracle, attestor verifier/source vault, manager/vault, registry, orchestrator, ingress, operator and governance addresses, callback gas, each subscription topic and status, funding transactions/reserves/debt, and per-attempt source/Lasna/destination evidence. Never record keys or credentials. Frontend needs manager ABI (`agreement`, `pendingDraw`, `principal`, `debtPreview`, `repay`, `DrawExecuted`, `DebtRepaid`), registry `RiskSignaled`/`latestGeneration`, Reactive `FinancialSignalObserved`/`FinancialCallbackRequested`/`requests`, and receiver `Disposition`/`Duplicate`/`records`. Display mock asset and simulated market clearly; never call a callback request a draw.

## Evidence procedure after separate authorization

Record signed terms, attestation and vault states before the signal. Save source receipt and `RiskSignaled` block hash, transaction hash and log index. Find the Lasna observation and callback request, then obtain the destination receipt, proxy caller/injected sender and receiver disposition. Reconcile manager `DrawExecuted`, operation ID, market debt, principal, vault cash/reservation, lifetime principal and eventual borrower repayment. Record source/reaction/destination block timestamps and independent observation times; report timeouts and negative clock deltas. The callback confirms neither source finality nor collateral evidence truth. Attestors independently apply an approved source-finality policy; no policy is established by this milestone.

For a temporary failure, verify the destination record is absent and manager state/pending operation before correcting the cause. If a Reactive request exists, operator may call `retry(triggerId)` after cooldown and within the three-attempt limit. If the initial system request reverted and no request exists, call `resignal(agreementId)` after its cooldown to re-emit the same still-eligible generation. Neither method resets financial state. Recovery, expiry, terminal state and duplicate receipts have distinct dispositions; do not re-request a terminal skip as though it were a failed delivery. After retry exhaustion there is no automatic reset; diagnose and reconcile, and use the existing permissionless manager path if appropriate. Live tests must separately confirm provider failure reporting and actual gas requirements.

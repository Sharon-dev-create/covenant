# Frontend integration handoff

Use ABIs compiled from this revision, never guessed ABIs: `CollateralVault`, `DemoToken`, `CreditLiquidityVault`, `TestnetCreditManager` / `CreditManagerCore`, `CollateralAttestationVerifier`, `DemoOracle`, `DemoMarket`, `RiskSignalRegistry`, `FinancialReactive`, and `FinancialCallbackReceiver`. `FinancialTrigger` is a library, not an address. Bind the reviewed manifest addresses by chain: Unichain Sepolia 1301 source vault; Base Sepolia 84532 demo token, market/oracle/adapter, verifier, manager/vault, registry and receiver; Lasna 5318007 reactive contract. Addresses are unresolved until actual receipts and checks exist. The demo token, values and market are simulated and must be visibly labeled.

Use EIP-712 v3 exact schema and normalized identifiers in [M2 signing vector](M2_SIGNING_VECTOR.md); borrower and lender independently sign nonces and deadlines. Lender approves the vault and deposits; the manager creates the agreement and activation reserves liquidity. Display collateral as locked on Unichain, attestation as pending/accepted/frozen/expired from the verifier, and distinguish claimed attestation finality from independently verified source finality. Never imply a release path exists.

After `RiskSignaled`, show source pending, then distinguish `FinancialSignalObserved` and `FinancialCallbackRequested` from actual delivery. Display receiver `Disposition` / `Duplicate`, including skipped, failed or retrying states. A request alone is not execution. Use Base manager `agreement`, `pendingDraw`, `principal`, `debtPreview`, `DrawExecuted` and `DebtRepaid` as financial authority; reconcile market debt, vault `free`/`reserved` and token cash. Repayment needs borrower token approval followed by `repay(id,amount,paymentNonce)`, with interest-first accounting and potential fractional carry. Show receipt confirmations and errors separately from indexing delays; do not display synthetic fixtures as live balances.

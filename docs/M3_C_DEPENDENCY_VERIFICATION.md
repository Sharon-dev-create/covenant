# M3-C demonstration dependency verification

Baseline revision: `93fc3da6366540945e41a1e71f8650ae9f984a56`; the pre-change complete suite passed 116 tests. All deployment and financial integration described here are local Foundry simulations, including use of synthetic test signing keys and simulated chain IDs. No operational attestor key was generated and no public transaction was made.

`CollateralAttestationVerifier` provides trusted threshold evidence, 30-minute maximum remaining validity, a 24-hour signer rotation delay and emergency pause as detailed in [COLLATERAL_ATTESTATION.md](COLLATERAL_ATTESTATION.md). The manager calls this verifier on activation and before execution, so pause and invalid evidence prevent both while repayment remains independent. No financial-engine source was modified.

`DemoToken` is a distinctly named cMOCK six-decimal simulated asset, with authority-only minting and a 100,000-token total supply cap. It is not Circle USDC. `DemoOracle` is operator-controlled and reports an explicitly simulated value per ETH with an update timestamp. For the scenario, `1,000,000e6` units per ETH values 0.001 test ETH at 1,000e6 units; the manager enforces its existing one-hour freshness. `DemoMarket` stores operator-controlled synthetic borrower debt and collateral/health; `DemoAdapter` fixes its asset, market and manager and clears market allowance. Neither is production market or price data.

`DemoDeploymentFactory` rejects asset runtime bytecode other than `DemoToken` and creates the existing `TestnetCreditFactory`, which atomically creates its testnet manager and vault. It checks the adapter's asset/manager, the market's asset and the verifier's manager, in addition to the nested factory's immutable manager/vault/dependency bindings. The pre-existing generic `TestnetCreditFactory` still permits other six-decimal assets; it must not be substituted for the demo factory. Code-hash and interface checks do not independently certify dependency behavior or issuer governance. The 300-unit per-agreement and per-manager lifetime limits remain those of the unchanged manager.

The local scenario binds and locks 0.001 test ETH under simulated Unichain chain ID, registers bilateral V3 terms on simulated 84532, accepts three synthetic signatures, deposits 1,000 cMOCK, reserves 300, and executes a signed 200 repayment against a simulated 800-debt/840-collateral market. External debt becomes 600, manager principal becomes 200, lender free liquidity becomes 800, and a subsequent borrower repayment while paused credits principal plus accrued interest to the same lender. The collateral remains locked. This is not live Reactive execution or proof of a finalized source event.

The focused suite covers threshold, duplicate/nonmember signers, exact binding and wrong domains, expiration and renewal, conflicting certificates, pause, rotation delay and new-epoch signatures, recovered position, stale/invalid oracle, exact financial behavior and injected external-market failure rollback. Attestor independence, canonical source-finality checks, emergency/rotation operations and live transport remain unverified.

## Local test and coverage results

On the final dependency implementation, formatting and forced build passed. The full suite passed 130 tests with zero failures or skips; the 1,000-run fuzz setting also passed 130. Fourteen focused M3-C tests are included. Coverage succeeded with optimization and viaIR disabled: verifier line/statement/branch/function 97.17/95.21/60.87/90%; demo adapter 92.31/77.27/0/100%; demo factory 92.31/96.88/50/100%; market 100/85.71/14.29/100%; oracle 100/82.35/25/100%; token 100/87.50/20/100%. Low reported branch coverage, including the adapter's 0%, is a material limitation of this evidence; do not infer that every failure mode or security property has been verified. This is not an independent audit.

The build retains existing naming, test-only selfdestruct and financial lint warnings. New verifier warnings include timestamp comparisons, bounded loop reverts, a zero-initialized signature bitmap and an unused reservation return from `agreement`; new dependency warnings flag code-length rather than explicit zero-address checks. The demonstration market updates debt before the token transfer, and a failed transfer reverts that state atomically. The contract roles and any timestamp/finality assumptions require separate testnet review.

The final existing financial invariant campaign passed 1,000 runs at depth 128 with `fail_on_revert=true`, seed `0x1234`, 128,000 handler calls and zero reverts. It exercises the existing local financial handler, not a stateful campaign of the new attestation verifier or simulated Base testnet dependencies. The local direct-call M3-C scenario and 14 focused tests supply separate evidence for those components.

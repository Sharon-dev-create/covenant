# M3-B shared financial engine verification

Base revision: `af1ccd40dc787ea675f2eedd842cc2b81042c419`. Implementation and tests are local only; no public deployment or broadcast occurred. The 108-test baseline passed before refactoring.

`CreditManagerCore` is abstract and contains the pre-existing financial logic once. Local `CreditManager` preserves the public constructor signature and requires chain 31337. `TestnetCreditManager` requires 84532 and enforces immutable 300e6 per-agreement commitment/principal caps and a 300e6 lifetime successful-draw cap per manager. Its fixed asset is a deployment-specified six-decimal token, not a verified issuer or global allowlist. The testnet wrapper and factory also require the adapter to have code; its market/asset and behavior remain dependencies checked by existing execution logic, not certified by deployment.

`LocalCreditFactory` remains unchanged; `TestnetCreditFactory` uses the same constructor-only predicted manager/vault creation and binding checks on 84532. The manager's non-reentrant draw path verifies the market, consumes liquidity, records the lifetime policy and principal atomically. Exceeding the remaining aggregate cap reverts all external effects. Repayment, default and cancellation never decrement the counter; a failed execution never increments it. Separate deployments have separate caps. There is no setter that increases the limits.

The local manager's EVM ABI is unchanged when Solidity `internalType` annotations are excluded; tuple fields, function/event/error wire signatures, constructor parameters and state mutability remain the same. Solidity source references to inherited struct/enum constructors and errors must use `CreditManagerCore.Terms`, `CreditManagerCore.State` and `CreditManagerCore` error selectors; the existing test source was updated accordingly without removing test cases. ABI `internalType` annotations change from `CreditManager` to `CreditManagerCore`, so generated source bindings may need regeneration. Contract bytecode and its gas cost also change. EIP-712 V3 typed data remains unchanged, while domain separation still binds chain ID and deployed manager address.

`M3BEngineTest` exercises simulated local and Base chain deployments, a shared draw/default/one-year-interest/full-repayment parity scenario, exact 300-unit draw, cap-plus-one rejection, lifetime cap across multiple agreements, failed market/over-cap rollback, non-replenishment after repayment/default/cancellation, nonce and cross-domain replay, six-decimal validation and immutable bindings. Its injected second-contract binding failure tests an isolated factory-pattern harness, not a production factory failure switch; production factory success and invalid-dependency rejection are tested separately. These tests do not prove arbitrary differential equivalence for every possible financial state.

M1-B live authentication/delivery/finality remain unverified. M3-C collateral-finality governance/verifier and M3-D financial Reactive callbacks are not implemented. No real-value origination, collateral release or liquidation is provided by this work.

## Verification and coverage

The final forced build and formatting check passed. The complete suite passed 116 tests, zero failures or skips; `forge test --fuzz-runs 1000` also passed 116. The 108 baseline tests are retained, with eight new M3-B tests. Foundry coverage (line / statement / branch / function) reported `CreditManagerCore` 99.26 / 96.72 / 76.79 / 100%, local wrapper 100 / 50 / 0 / 100%, testnet wrapper 100 / 91.67 / 66.67 / 100%, `LocalCreditFactory` 94.74 / 95.83 / 33.33 / 100%, and `TestnetCreditFactory` 94.74 / 94 / 0 / 100%. Constructor/branch coverage has source-map limitations; 0% reported factory branches is not proof that those branches were untested or covered. Coverage disables optimizer and viaIR and is not an audit.

Pre-existing warnings include four `agreement` naming collisions, test-only `selfdestruct` deprecation, reentrancy/equality/timestamp/rounding lint and optional invariant-discovery warnings. The refactor adds two `empty-block` lint warnings for the deliberately empty local policy hooks. These hooks intentionally preserve local behavior, while the manager's existing reentrancy guard covers the testnet post-repayment policy hook.

The final local `CreditFinancialInvariant` campaign passed with `FOUNDRY_INVARIANT_RUNS=1000`, depth 128, `FOUNDRY_INVARIANT_FAIL_ON_REVERT=true` and seed `0x1234`: 128,000 handler calls, zero reverts. This existing stateful invariant targets the local wrapper; the testnet wrapper's lifetime and parity behavior is covered by the separate deterministic M3-B tests, not by a testnet stateful invariant campaign.

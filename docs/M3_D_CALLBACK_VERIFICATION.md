# M3-D local financial callback verification

Baseline revision `93fc3da6366540945e41a1e71f8650ae9f984a56`, with pre-existing M3-C work unstaged. The baseline full suite passed 130 tests. This milestone is **local simulation only**: the mock Lasna system and Base callback proxy do not prove live delivery, billing or source finality.

## Implemented boundary

`RiskSignalRegistry` is a Base-only signal registry pinned to a manager and simulated market. Permissionless `signal` checks the Active signed agreement, current market debt/health and deadline; one generation stays outstanding and cannot be overwritten by repeated calls. `resignal` re-emits the same eligible generation after 60 seconds, allowing recovery if the first system callback request reverted before a request was stored. `retire` permits a new generation only after recovery, insufficient debt, expiry or a terminal agreement. These events do not authorize a draw or carry a discretionary amount.

`FinancialReactive` is Lasna-only. Its immutable operator configures one fixed Base registry, manager and receiver and an explicit 1,000,000–3,000,000 callback-gas range. It subscribes to the exact `RiskSignaled(bytes32,uint64,address)` topic and fixed manager; only the pinned system can call `react`. It validates the source chain, emitter, opcode, topics and nonzero block/transaction hashes. Trigger identity is domain-separated and fixes reactive, receiver, source/destination, manager, agreement and generation. A request event records **a request only**, not execution. Re-emitted identical semantic signals do not issue a second request; their observed source identity is logged, not treated as a source-finality proof. The first observation's source identity is retained for reconciliation. Operator `retry` is limited to three total requests with 60-second cooldown; no automatic protocol redelivery is assumed. If the first system request reverts, the Reactive transaction and its observation revert, and `resignal` can create a fresh source event for the same generation. Once all three requests are exhausted there is no in-contract reset; investigate state and use the existing permissionless manager execution if appropriate. Stop unsubscribes permanently for that instance.

`FinancialCallbackReceiver` is Base-only and checks the configured Base proxy, injected reactive address, exact ABI length and domain/route/trigger fields. It reads the registry and existing manager and either calls `observeRisk` when no pending operation exists or uses the existing manager pending operation; it reads the exact amount from the signed agreement and calls `executePending`. Manager collateral attestation, oracle, market, signed conditions, atomic accounting and testnet caps are unchanged. No separate debt ledger exists.

## Disposition and failure

Wrong proxy, injected sender, route, encoding or ID reverts without a record. A duplicate returns an event pointing to the original disposition, with no financial call. Unknown, recovered, expired, terminal and stale generations record distinct skip outcomes; an already Drawn agreement records `AlreadyDrawn` without fabricating an operation ID. A recovered signal clears an existing ineligible pending operation via the manager and retires the hint. An expiry skip does not itself cancel a reservation: call `expireUnused` separately. Temporary manager, collateral, token, oracle, market, adapter or other dependency failures bubble as a revert, rolling back the callback record and any manager/market/vault state in that transaction; a pre-existing pending operation remains pending. A successful callback records `Executed` and operation ID only after the manager's completed-draw and principal checks succeed. Competing direct execution remains permitted by M2 and is reconciled from manager state and `DrawExecuted`.

## Local integration evidence

The simulated lifecycle uses a real local `CollateralVault`, M3-C trusted attestation with synthetic test keys, cMOCK, simulated oracle/market and a mocked Omni system/proxy. A 1,000-unit lender deposit and 300-unit reservation led to a 200-unit callback-driven draw: market debt 800 -> 600, manager principal 0 -> 200, lender free liquidity 700 -> 800 and lifetime principal 0 -> 200. A later repayment restored lender cash including accrued interest. The test checks callback request alone leaves debt and reservation unchanged, duplicate delivery has no extra effect, and collateral remains locked. Additional tests cover wrong sender/proxy and encoding, forged source logs, duplicates, recovery, expiry, terminal state, stale/unknown signals, competing direct executor, pause, bounded retry, a failed initial system request and a later re-signal, and market/adapter failure rollback. Direct adapter tests inject failed token transfer, approval and approval cleanup, and an incorrect reported market repayment; they assert financial rollback. These are not live provider tests.

## Measurement boundaries

An optimized local trace measured approximately 842,951 gas for registry creation, 1,238,093 for reactive creation, 1,135,346 for receiver creation, 146,293 for `signal`, 463,051 for `react` against a mock system, and 635,819 for the successful receiver call including manager execution. These are internal local trace gas, not public-network transaction gas, not L1 data fees and not proxy overhead. The 2,000,000 callback configuration used in tests is provisional; the mock proxy does not enforce real Omni gas withholding. Re-estimate after implementation with actual addresses, provider overhead and fee-oracle data.

The receiver must check **both** `msg.sender == callback proxy` and the injected address, because either check alone is insufficient. |
| Callback proxies | Unichain Sepolia `0x775c9B990ADe401060B78D0e98684eEf8d2466C1`; Base Sepolia `0x476F44b11F5C942c58f4c8E3d0300E5710743585`; Lasna `0x8888888888888888888888888888888888888888`. |

Direct transfers raise a contract balance but do not clear debt unless `pay()` settles it. Any debt blocks execution. |

## Implemented M1-B transport

`CovenantTransportReactive` installs one exact subscription per route: source chain, emitter, `topic0`, `REACTIVE_IGNORE` for topic1, the numeric route in **topic2**, and `REACTIVE_IGNORE` for topic3. The emitter's `ProbeRequested` topics are `[signature, operationId, route, sequence]`; putting the route in topic1 would filter out every real log. `react()` is System-only and validates the full envelope, source identity, decoded data, route, operation digest and sequence before requesting a callback. A callback request only increments the attempt counter; only the receiver's `ProbeReceived` and `received(sequence)` state record destination success.

Both probe contracts implement the documented Omni payer surface locally: `receive()`, provider-only `pay(uint256)`, public `coverDebt()` and an immutable `_SERVICE_PROVIDER()` getter. This avoids a dependency on the full Omni library while preserving the ABI and settlement behavior needed for live funding. The reactive contract's provider is the Lasna System; each receiver's provider is its chain's callback proxy. Prefer `depositTo(address)` for reserves; direct funding works because `receive()` exists and `coverDebt()` can apply it.

## Authentication and trust boundaries

| Fact | Evidence and limit |
|---|---|
| Authentic callback delivery | `msg.sender` must be the pinned callback proxy and the injected first argument must be the expected Lasna reactive contract. This trusts the proxy implementation, its signer/upgrade authority and Reactive delivery. |
| Observed origin event | The System invokes `react()` with a normalized log. The contract validates the subscription envelope, source metadata, indexed topics and operation digest. This is a Reactive observation, not an external-chain receipt proof. |
| Finalized source state | Reactive finality applies to Lasna blocks only. The reviewed material gives no source confirmation-depth, canonicality or reorg-recovery guarantee. A source RPC finalized tag carries RPC trust and is not an on-chain verifier. |
| Successful destination execution | A destination receipt with matching `ProbeReceived` and receiver state establishes observed execution. A Lasna `CallbackRequest`, an empty `getCallbacks()` result or a successful outer proxy receipt does not. Destination finality is checked independently. |

A future financial gate could use a 3-of-5 independent finalized-source attestation quorum, subject to explicit design approval. Each attestor would derive the source rollup's finalized view from independently operated rollup and Ethereum nodes, then verify the canonical block, receipt, log index, emitter, topics and data. Signatures would cover an EIP-712 statement binding those facts, the operation, intended action, receiving chain and verifier, deployment domain, expiry and signer epoch. A destination verifier would enforce distinct active signers, matching transport intent and one-time application. This design still trusts the quorum, key rotation and underlying chains. The probes implement no finalized attestation or financial action. ## Future financial lifecycle design

Use the Omni contract library pinned to the reviewed commit in M1. Lasna chain ID is 5318007; fund deployment with lREACT and post reaction reserves separately. Register the CovenantReactive contract itself through the Omni system contract using `subscribe(uint256,address,uint256,uint256,uint256,uint256)`. Use `unsubscribe` with the identical filter. Restrict `react(LogRecord)` to the system, recheck chain, emitter and topic signature, strictly decode indexed fields and data, and validate topic widths. Track subscription configuration and check live registration with `rnk_getFilters`/`rnk_getFilterById`. Deploy the Reactive contract first, deploy receivers pinning it, then configure one-time verified routes and register exact emitters. Keep routing inactive until configuration and funding checks pass.

Request callbacks with `requestCallbackV_1_0`, passing chain ID, recipient, gas limit and an ABI payload whose first argument is an `address(0)` placeholder. Every ingress checks the exact destination proxy as `msg.sender` and the exact injected reactive contract address. Use distinct receivers for gas billing, especially on Unichain. Pin proxies from [network evidence](NETWORK_VERIFICATION.md). The emitters and receivers below are deployment-specific Covenant addresses and remain future work.

| Source and canonical topic0 signature | Indexed topics and decoded data | Reaction and destination callback | Identity and application |
|---|---|---|---|
| Unichain 1301 CollateralVault, `CollateralLocked(bytes32,bytes32,address,uint256,bytes32,bytes32)` | topic1 agreement, topic2 lot, topic3 borrower; data amount, termsHash, opId | Queue lock intent → Base 84532 ingress `confirmLock(address,bytes32,bytes32,address,uint256,bytes32,bytes32)` | Authenticate proxy/RC, recompute opId with fixed lock sequence 1 and exact payload; stage and finalize only with matching finalized assertion. |
| Base 84532 CreditManager, `RiskObserved(bytes32,uint64,bytes32,uint64)` | topic1 agreement, topic2 epoch, topic3 drawId; data expiry | Queue execute → Base 84532 ingress `execute(address,bytes32,uint64,bytes32)` | Authenticate proxy/RC, check drawId, stored epoch and expiry against Base state. |
| Base 84532 CreditManager, `ReleaseApproved(bytes32,bytes32,address,bytes32)` | topic1 agreement, topic2 lot, topic3 borrower; data opId | Queue release → Unichain 1301 ingress `release(address,bytes32,bytes32,address,bytes32)` | Authenticate proxy/RC; recompute opId with fixed release sequence 1; apply only with matching finalized assertion. |

Topic0 is Keccak-256 of the exact signature. In initial per-deployment subscriptions use `REACTIVE_IGNORE` for topics 1–3 where the future event does not pin a route; decode and validate all indexed fields. Integers decoded from topics must fit their ABI widths. Stage transport metadata for bounded application-level re-requests on Lasna; canonical sink state determines execution.

## Delivery, recovery and funding

Treat delivery as duplicate-prone, arbitrarily delayed and possibly absent. Reactive consensus finality is separate from external source finality. No source-depth SLA, message-order SLA or automatic application-level redelivery guarantee was verified. Use independently authenticated finalized proofs for lock and release. Base-to-Base risk callbacks treat a reorged/unknown epoch as ineligible. Lag and outages fail closed.

Read system `getCallbacks(uint256)` by reactive transaction hash, destination receipt, proxy `CallbackFailure`, and protocol event/state. A successful proxy-level transaction or empty callback record proves no application outcome by itself. For a failed funding or execution, correct the cause and request the same semantic operation. The probe's application-level re-request uses a stored authenticated payload, fixed receiver, cooldown and per-operation attempt cap; a scoped operator may use it only after auditing destination state. Never alter a consumed intent to force success.

Maintain lREACT reserves for reactions and native ETH reserves on each callback proxy for its own receiver, using `depositTo(address)`. Measure receiver gas including proxy overhead for each route and use limits above the documented 100,000 floor. Insufficient recipient funding/debt can suppress delivery; failed callbacks still cost gas. See [economy](https://dev.reactive.network/economy), [callback authentication](https://dev.reactive.network/callback-contracts), and [diagnostics](https://dev.reactive.network/debugging).
